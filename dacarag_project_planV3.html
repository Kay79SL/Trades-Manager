Retrieval Orchestration

Thursday 30 April • ~2h • camel
0 / 0
▾
WhyThe query router is what makes a hybrid RAG smarter than a plain vector RAG. It decides per question whether to use vector search, graph traversal, or exact lookup — and combines results before the LLM sees them.
  1. Create retrieve\router.py — classify query intent: semantic, relational, exact_lookup, or predict_quote
  2. Create retrieve\vector_search.py — top-k cosine similarity from Atlas Vector Search
  3. Create retrieve\graph_search.py — three Cypher templates: customer history, similar past jobs, multi-hop supplier paths
  4. Create retrieve\mongo_lookup.py — fetch full documents by id or filter
  5. NEW: Create retrieve\predict_quote.py — the pricing intelligence layer. For a given job_type_id, aggregates labour cost statistics from past invoices (Mongo), pulls typical materials with quantities and unit prices from Neo4j (USES_ITEM edges), cross-checks against POs for the same job_type, and returns a structured quote prediction with confidence and basis.
    6. {
  "job_type_id": "pl_01",
  "job_name": "Boiler installation",
  "predicted_labour_eur": 450,
  "labour_range_eur": [400, 520],
  "predicted_materials_eur": 1262,
  "typical_materials": [
    {"item_id": "it_pl_009", "name": "Gas boiler 24kW", "qty": 1, "price": 1100},
    {"item_id": "it_pl_026", "name": "Boiler flue kit", "qty": 1, "price": 85},
    ...
  ],
  "predicted_total_ex_vat": 1712,
  "predicted_total_inc_vat": 2106,
  "confidence": "high",
  "based_on": {"past_invoices": 8, "pos": 1, "median_or_avg": "median"}
}
    This is the killer feature — it uses ALL THREE storage stores in one query path: Mongo for historical statistics, Neo4j for canonical recipes, and POs for current market quotes. Demonstrates polyglot persistence in action.
  6. Create retrieve\context_assembler.py — merge results from all three paths, dedupe, rank, build LLM prompt
  7. Test each route independently with one query each
    8. python -m retrieve.vector_search "lights flickering kitchen"
python -m retrieve.graph_search "What did Sean Murphy have done last?"
python -m retrieve.mongo_lookup "INV-2025-0001"

    If "dacaragacr" is taken, try "dacaragacr2026" or another suffix. ACR names must be globally unique.
  9. Build the image in the cloud (no local Docker required)
    10. cd F:\Apps\DACARag
az acr build --registry dacaragacr --image dacarag:v1 .
    This uploads your code to Azure, builds the Docker image there, and pushes it to your registry. Takes 3-5 minutes the first time. Watch the logs stream in your terminal.
  10. Sub-phase C — Deploy to Azure Container Apps. Install the Container Apps extension
    11. az extension add --name containerapp --upgrade
az provider register --namespace Microsoft.App
az provider register --namespace Microsoft.OperationalInsights
  11. Create a Container Apps environment
    12. az containerapp env create \
  --name dacarag-env \
  --resource-group dacarag-rg \
  --location northeurope
  12. Get your ACR credentials (needed for the deploy step)
    13. az acr credential show --name dacaragacr
    Note the username and password from the output — you'll paste them in the next step.
  13. Deploy the chatbot — replace the placeholders with your real values
    14. az containerapp create \
  --name dacarag-chat \
  --resource-group dacarag-rg \
  --environment dacarag-env \
  --image dacaragacr.azurecr.io/dacarag:v1 \
  --target-port 8501 \
  --ingress external \
  --registry-server dacaragacr.azurecr.io \
  --registry-username <ACR_USERNAME> \
  --registry-password <ACR_PASSWORD> \
  --env-vars \
    MONGO_URI=secretref:mongo-uri \
    MONGO_DB=trades_quotes \
    NEO4J_URI=secretref:neo4j-uri \
    NEO4J_USER=neo4j \
    NEO4J_PASSWORD=secretref:neo4j-pwd \
    ANTHROPIC_API_KEY=secretref:anthropic-key \
  --secrets \
    mongo-uri=<your_full_mongo_uri> \
    neo4j-uri=<your_neo4j_uri> \
    neo4j-pwd=<your_neo4j_password> \
    anthropic-key=<your_anthropic_key> \
  --cpu 0.5 --memory 1.0Gi \
  --min-replicas 0 --max-replicas 1
    Use secretref: for sensitive values. Never bake passwords into the image. --min-replicas 0 means the container shuts down when idle, saving credit.
  14. Get the public URL of your deployed chatbot
    15. az containerapp show \
  --name dacarag-chat \
  --resource-group dacarag-rg \
  --query "properties.configuration.ingress.fqdn" \
  --output tsv
    Output looks like dacarag-chat.lemonbeach-abc123.northeurope.azurecontainerapps.io. Open it in a browser — your chatbot should load!

    16. az containerapp logs show --name dacarag-chat --resource-group dacarag-rg --follow
  16. Visit the URL, ask the chatbot 5 questions, verify it works end-to-end (using your Atlas + AuraDB cloud databases)
  17. Sub-phase E — Clean up to save credit. Stop the app when not using it
    18. az containerapp update --name dacarag-chat --resource-group dacarag-rg --min-replicas 0 --max-replicas 0
  18. When done experimenting, tear it all down (preserves credit for future projects)
    19. az group delete --name dacarag-rg --yes --no-wait
    This deletes EVERYTHING in the resource group: the app, the registry, the environment. Use this when you're sure you're done.
